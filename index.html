Parameterized Argumentative Reasoning Task (PART)

Reasoning powers modern language, but its effects on performance prove to be brittle and opaque, which prohibits them from being responsibly applied in law and evidential reasoning. In this shared task, teams solve reasoning puzzles about witness testimony. Each puzzle is a synthetic case text generated from a formal argumentation attack graph — certain testimonies attack others, rendering them “unbelievable”. The model must recover the underlying attack graph from the natural language and decide what can be believed.

The task

Teams are tasked with solving reasoning puzzles concerning witness testimony. Based on a synthetic case text, the goal is to answer binary yes-or-no questions about a particular testimony, or to answer which witnesses can be believed. The puzzles are represented in natural language generated from formal argumentation graphs, where certain testimonies attack others thus rendering them “unbelievable”.

The underlying structure of each puzzle is a directed attack graph, which language models will need to extrapolate from the natural language case text representation in order to solve the task.

Subtasks

We split the overall goal of the shared task into two subtasks: a binary task and a multi-label task. Participants can take part in either or both.

Task 1 · Binary prediction

Determine the believability of a specific statement that was mentioned in the case text.

Input: case text + statement · Output: yes or no

Task 2 · Multi-label prediction

Determine which witnesses mentioned in the case can be believed.

Input: case text · Output: list of names of believable witnesses

Example puzzle

An illustrative reasoning puzzle based on a non-linear attack graph with four arguments (Steging et al., 2026a). The model sees only the natural language; it must reason over the hidden attack structure.

Dataset

The dataset is based on the dynamic benchmarks introduced in Steging et al. (2026a). Each instance contains two prompts: a binary prompt and a multi-label prompt, each describing the case text and task instructions. We release training and test data for both tasks.

Puzzles vary in complexity, expressed primarily by the number of nodes and shapes of the underlying argumentation graph. Witness testimonies may be presented in order, shuffled, and irrelevant testimonies unrelated to the main argument may be included. Different types of attack relations, statements, witness names, irrelevant information, and prompt configurations may be expected to ensure generalizability.

Note on distribution: the test set may differ in distribution from the training set. Specifically, expect shifts in the number of nodes and shapes of the underlying argumentation graphs, the order in which witness testimonies are presented (in order or shuffled), the presence of irrelevant testimonies, the types of attack relations, the statements and witness names, and the prompt configurations. Teams should not assume that test puzzles follow the same distribution as the training data.

Modeling restrictions

  • Models are restricted to open-source models with a total of 8B parameters or less. Intermediate steps may use larger models, for instance for distillation.
  • Mixture-of-experts models count as the total parameter count; ensembles of several models count as the sum of their weights.
  • Teams may use any training data, models, and frameworks, provided the model weights can be released under a license with unrestricted non-commercial use (e.g. Apache, MIT, CC-BY).
  • The use of closed commercial APIs is prohibited
  • Per subtask, teams may submit a maximum of three runs.

Evaluation

Task 1 · Binary

Primary: F1 score on classification performance.

Also reported: the underlying precision and recall scores in the final analysis.

Task 2 · Multi-label

Primary: strict accuracy — the predicted list of believable witnesses must match the ground-truth list exactly (order is not taken into account).

Secondary: micro F1 on the number of correctly classified witnesses.

Evaluation is run offline. Alongside the evaluation of the teams, the organizers will also run simplistic baselines.
